0–5 min · Start with a real problem

Why do search results sometimes miss what we mean?

Think about searching a phone support website. You type “My battery runs out too fast.” The helpful guide is called “How to improve battery life.”

The two sentences use different words, but they describe the same problem. A basic keyword search mainly looks for matching words, so it may not find the best guide.

🔎 What the user types“My battery runs out too fast.”
📄 What the guide says“How to improve battery life.”
💡 What connects them?They have a similar meaning.
The key question: Can a search system find useful information based on meaning, not just matching words?

Yes. Semantic search does this by turning text into numerical representations called embeddings. It compares those representations to find text with a similar meaning. In the next section, you'll learn how this works.

Three ideas that power semantic search

Core lesson: read the short explanations first, then open the deeper-theory panels when you want to understand the model mechanics and system design behind the demonstrations.

1. Embeddings: text becomes a vector

An embedding is a numerical representation of an input, such as a sentence. An embedding model processes text and outputs a fixed-length list of numbers. In this lesson, the MiniLM model produces 384 values for each sentence.

“I need help
signing in”
→
Embedding
model
→
[0.12, −0.08,
0.31, …]

No single dimension has a simple label like “happiness” or “login”. The learned pattern across the vector is what carries useful information.

Big picture: an embedding model learns a function that maps an input into a point in a high-dimensional vector space. Inputs that are useful to treat as related are encouraged, through training, to have related representations.
Deeper theory 1 · What happens inside an embedding model?

A sentence embedding model is usually built around a neural language encoder. A simplified view of the process is:

Tokenization: text is split into tokens and mapped to token IDs.
Token embeddings: token IDs are converted into learned numerical representations, with positional information added.
Contextual encoding: Transformer layers use self-attention so each token representation can incorporate information from other tokens in the input.
Pooling: token-level representations are combined into one fixed-size sentence representation. This lesson uses mean pooling.
Normalization: the resulting vector is scaled to unit length in this application, making dot product equivalent to cosine similarity.

Important distinction: a language model may produce a representation for every token. A sentence embedding model adds a pooling step to create one vector for the whole input.

In this project, Transformers.js calls the pretrained Xenova/all-MiniLM-L6-v2 feature-extraction pipeline with mean pooling and normalization. The interface displays only the first 12 values, while the model returns a 384-dimensional vector.
Deeper theory 2 · How does a model learn useful embeddings?

Embedding models are trained on examples so that their vector space becomes useful for a task. For sentence similarity, training often uses pairs or groups of texts and a learning objective that encourages related examples to be closer (or more aligned) than unrelated examples.

One common family of approaches is contrastive learning. Imagine a query and a relevant passage as a positive pair. Other passages in the batch may act as negatives. Training adjusts the encoder so the positive pair receives a stronger similarity than the negatives.

Positive pair“I can't sign in” ↔ “Recover a forgotten password”
Negative pair“I can't sign in” ↔ “Today's weather forecast”
Learning goalMake useful relationships easier to retrieve in vector space.

The exact training data and objective depend on the model. At use time, we generally run the trained encoder to generate vectors; we are not retraining it for each search.

Deeper theory 3 · Vectors, dimensions and distance

A vector is an ordered list of numbers. A 384-dimensional embedding has 384 coordinates. We cannot usually interpret one coordinate in isolation; meaning is distributed across the pattern of values.

Geometrically, each vector is a point and a direction in a 384-dimensional space. Similarity functions compare the relationship between two vectors. Cosine similarity focuses on the angle, not their raw lengths.

cos(θ) = (A · B) / (||A|| × ||B||)

Here, A · B is the dot product and ||A|| is the vector magnitude. Because this project normalizes vectors to unit length, the denominator is 1 and the dot product gives cosine similarity.

Interpretation: a larger score often indicates stronger semantic relatedness for this model and task. It is not a probability, a percentage of shared meaning, or a universal quality threshold. Scores should be interpreted by comparing candidate results and testing representative queries.

Deeper theory 4 · Dense search, sparse search and hybrid retrieval

Sparse / keyword retrieval represents text using terms and their weights. Methods such as BM25 reward useful term matches and are strong when exact names, IDs, product codes or rare words matter.

Dense retrieval represents text as dense vectors and compares them in an embedding space. It can retrieve related wording even when the exact terms differ.

Hybrid retrieval combines both signals. A production system may also rerank the candidates with a more detailed model, apply metadata filters, or check whether the best score is strong enough to return a result.

The keyword score in this teaching app is intentionally a simple word-overlap baseline, not a full BM25 implementation. It is included to make the contrast easy to observe.
Deeper theory 5 · From semantic search to a vector database

When a knowledge base grows, calculating similarity against every stored vector can become expensive. A vector database or vector index stores embeddings alongside IDs and metadata, and provides efficient nearest-neighbour retrieval.

Many systems use approximate nearest-neighbour (ANN) indexes. ANN methods trade a small amount of exactness for much faster retrieval at scale. The application can then fetch the original text associated with the selected vector IDs.

For documents, the usual preparation steps are:

  1. Split documents into meaningful chunks.
  2. Generate an embedding for each chunk.
  3. Store each vector with its text, source and metadata.
  4. Embed the user's query using the same compatible model.
  5. Retrieve the nearest chunks and optionally rerank them.

Chunk size matters: chunks that are too large can mix unrelated ideas; chunks that are too small can lose useful context. Overlap can preserve continuity between neighbouring chunks.

Deeper theory 6 · How do we evaluate retrieval quality?

A high similarity score alone does not prove that a result is useful. Build a small set of realistic queries and label which documents are relevant. Then evaluate whether relevant documents appear near the top.

  • Precision@k: among the first k results, what fraction are relevant?
  • Recall@k: of all known relevant documents, what fraction appear in the first k?
  • MRR (Mean Reciprocal Rank): how high is the first relevant result, averaged across queries?

Also test edge cases: ambiguous queries, misspellings, negation, very short queries, domain-specific terms and queries with no good answer. A responsible search experience should be able to say that no sufficiently relevant result was found.

2. Vector space: relationships become geometry

Think of each vector as a point in a high-dimensional space. Texts that are related in the model's learned representation often have vectors pointing in similar directions. Our model uses 384 dimensions, so the real space cannot be drawn on a normal screen.

Important: A 2D picture of embeddings is only a projection or illustration. It can help intuition, but it cannot show all relationships in the original 384-dimensional space.

3. Cosine similarity: compare vector direction

Cosine similarity compares the angle between two vectors. It is commonly used to estimate how aligned their directions are.

cosine(A, B) = (A · B) / (||A|| × ||B||)
Near +1Vectors point in similar directions.
Near 0Vectors are close to perpendicular.
Near −1Vectors point in opposite directions.

Scores are model- and task-dependent. A high score is a similarity signal, not proof that two sentences mean exactly the same thing.

What does this teach us?

Embeddings can capture topic and contextual relationships, but they may not reliably handle every logical detail. For example, adding “not” can reverse a statement while leaving much of its topic unchanged. Similarity alone should not be treated as a complete understanding of truth, intent, or sentiment.

Design takeaway: Production search systems may combine embeddings with keyword search, metadata filters, reranking, or other checks to improve reliability.

How real AI applications use embeddings

Semantic retrieval is often one component of a larger system. In Retrieval-Augmented Generation (RAG), an application retrieves relevant passages and supplies them to a language model as context for an answer.

What happens after retrieval?

Semantic search is a retrieval step, not automatically a complete answer-generation system. In a RAG application, the retrieved passages are passed to a language model with the user's question. The language model then writes an answer using that supplied context. The quality of the final answer depends on both retrieval quality and generation behaviour.

Remember: embeddings help locate candidate information. They do not verify that a passage is true, guarantee that it answers the question, or generate the final response by themselves.

Other practical applications

Product discoveryFind products by describing needs.
Support routingMatch a ticket to the right team or article.
RecommendationsFind content related to user interests.

What a simple implementation looks like

from sentence_transformers import SentenceTransformer, util model = SentenceTransformer("all-MiniLM-L6-v2") docs = ["Reset your password in Settings", "Cancel anytime from Billing"] doc_vectors = model.encode(docs, normalize_embeddings=True) query_vector = model.encode( "I cannot access my account", normalize_embeddings=True ) scores = util.cos_sim(query_vector, doc_vectors)[0] best_index = scores.argmax() print(docs[best_index])

This is an illustrative Python equivalent using Sentence Transformers. The interactive lesson itself runs its embedding model in the browser with Transformers.js.

Good system design: use the same compatible embedding model for documents and queries; split long documents into meaningful chunks; evaluate retrieval quality; and decide what to do when no result is relevant enough.
